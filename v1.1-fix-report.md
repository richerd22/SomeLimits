# SomeLimits v1.1 - UX rescue report

Trigger: the first real playtest failed the acceptance test. The
playtester hit New and got a screen that read as half a coaster with
no clear next step - and undoing made it more confusing, not less.

## Diagnosis (from the v1 code, play/index.html)

### 1. There was no "New" - and what boot showed instead could be half a coaster
- v1 shipped **no New button anywhere**. The closest gestures were the title
  card's "start building" - whose handler was literally
  `$('titleScreen').classList.remove('open')`, i.e. it created nothing - and
  the preset buttons.
- What "start building" revealed was whatever `boot()` had loaded, in this
  order: share link > **autosave** > classic preset. The autosave
  (`somelimits-autosave-v1` in localStorage) is rewritten on *every* commit,
  including innocent fiddling, so a returning session silently opens on the
  last half-edited track, with no label saying "this is your old draft, not a
  new coaster." On a clean browser the default was the complete classic
  circuit - but:
- The camera was parked at one fixed position (60,55,85) aimed at (10,8,0),
  never fitted to the track. The loop's return leg sits far side, partly
  behind the 252px editor panel at common window sizes, so a complete,
  closed circuit genuinely reads as "half a coaster" at first glance. And
  nothing on the first screen said the track in front of you is closed and
  rideable as-is.

### 2. Undo crossed document boundaries
- One global `history` array served every document. Boot seeded it with the
  restored autosave; **preset loads and file imports called `commit()`**,
  pushing the new document onto the *old* document's stack. So pressing
  Ctrl+Z a few times near the bottom didn't undo your last edits - it swapped
  the whole coaster for a different one (and redo swapped back). That is the
  "undoing made it more confusing" mechanism, exactly.
- The one path that did it right - library "open" reset the history first -
  proves the inconsistency was accidental, not designed.
- The undo button did disable at `hIndex <= 0`, but that couldn't help: the
  stack itself contained multiple coasters, so the "floor" was a different
  document, not the start of this one.

### 3. Zero-tutorial affordances were missing
- No New control (above). The only instructions were a dense paragraph at
  the bottom of the side panel plus the MANUAL overlay - both easy to never
  see. Nothing framed the whole coaster on load, and nothing said "this is
  complete, press RIDE IT."

## Fixes shipped (v1.1, same file)

- **Real NEW button** (editor panel, next to save/undo/redo).
  `newDocument()`: loads the classic preset as the document (complete,
  closed, rideable - see verification), names it "new coaster", resets
  history so this document is the floor, overwrites the autosave with it
  (a stale half-coaster can no longer resurrect as "new"), frames the whole
  loop, and toasts "complete and rideable right now... or just hit RIDE IT."
  Confirms before discarding unsaved edits (library saves untouched).
- **Per-document history.** New `resetHistory()` (history = [current doc])
  now runs on every document load: New, presets, library open, file import.
  Undo can never leave the document you are in. This is the v1 bug's direct
  fix.
- **Undo floor teaches.** At the bottom of the stack the button is disabled
  (as before) and Ctrl+Z / the button now toasts "nothing to undo - this is
  the coaster you started with" instead of silently doing nothing.
- **`frameTrack()`** fits the camera to the track's bounding volume
  (center + distance from FOV) and runs on boot, New, preset load, library
  open, and import. First screen now shows the entire closed loop.
- **One-line hint bar** across the top of the editor (not a tutorial):
  "drag the lime dots to shape it - double-click the track to add a point -
  RIDE IT when ready". Hides in ride mode.

Sacred rules untouched: one closed spline, banking lives on the point,
auto-lift on 8m+ climbs, drag smoothing on release, no modes or menus added.

## Verification (headless, Node + three@0.160, shipped code extracted verbatim)

- Full module passes `node --check`.
- **New-doc circuit:** `computeTrack(PRESETS.classic)` - first sample ==
  last sample (closed), station + lift present, length 286m; simulated ride
  completes a full lap unaided: **47.8s, max 86 km/h, max G 7.0** (matches
  v1's verified classic numbers).
- **History semantics** (the actual `snapshot/commit/applyState/
  resetHistory/undo/redo/syncHistoryButtons` sources extracted from the file
  and exercised with DOM stubs):
  - boot/New seed exactly one baseline; undo button disabled at the floor;
  - 3 edits + 3 undos lands exactly on the new document; a 4th undo changes
    nothing and fires the explanatory toast; redo still works;
  - after a preset load (resetHistory path), undo cannot reach the previous
    document - the v1 regression case passes.
- Not verified: WebGL rendering itself (no GPU in the sandbox) - same
  caveat as v1; the render code paths changed only additively
  (frameTrack/hint/New call existing buildTrack/setMode machinery).

## Acceptance test, as now specified

Open page > NEW (or just start building) > the whole classic circuit is in
frame with the hint bar on top > press RIDE IT > full lap, zero edits.
Undo at any point can only walk back through this session's edits, and says
so when it reaches the start.
