# Mobile rendering and lazy library previews

Updated November 18, 2026. No new editor mode, no generated imagery, and no game build step.

## Why this exists

The previous rounds reduced unnecessary track rebuilding and expensive support checks. Two costs remain on devices with high pixel density or large local coaster libraries.

### 1. High-DPI phone fill cost

The Three.js renderer originally called `renderer.setPixelRatio(devicePixelRatio)` with no cap. An iPhone reporting DPR 3 renders **nine backing pixels per CSS pixel** (3 x 3). DPR 2 uses **four backing pixels per CSS pixel** (2 x 2). A cap of 2 therefore avoids 5 of every 9 raster pixels, a theoretical **55.6% reduction in color-buffer pixel count** on a DPR 3 device. It is **not** a measured FPS or battery improvement.

The game now uses `gamePixelRatio(dpr)` with a 1-2 range (invalid values fall back to 1). Desktop DPR 1 and Retina DPR 2 remain unchanged. Resize applies the current capped DPR if the browser window moves between displays, then updates renderer size. No custom settings, asset changes, or user-visible controls are added.

Deliberate tradeoff: a very high-DPI phone loses some subpixel sharpness compared with native 3x, to make the 3D builder more sustainable on mobile. The game's UI is still browser text at its normal CSS resolution.

### 2. Eager library thumbnails

A saved coaster's blueprint is generated by `blueprint(nodes)`, which computes a 900-sample spline and draws a top-down image on a canvas. Storing that PNG in localStorage was removed in the previous round, but `renderLib()` still called `libraryBlueprint(entry)` **for every library entry** synchronously when the library opened. Hundreds of saved coasters would turn opening the library into a burst of expensive, mostly invisible spline work.

The updated library builds card text/buttons immediately and reserves a 3:2 thumbnail slot in CSS. `IntersectionObserver` watches images with a 180px prefetch margin. Only cards near the viewport generate their thumbnails; previously visible cards keep a cached result. Rebuilding the library disconnects its previous observer before attaching a fresh one. Older browsers without `IntersectionObserver` eagerly render thumbnails as before, instead of displaying blank cards.

The in-memory thumbnail cache is bounded to **40 entries** and uses least-recently-used ordering. Editing a coaster changes the JSON node signature and invalidates the cached preview. Deleting a saved coaster evicts its cache entry after a successful library write. Library saves remain source-node-only: no PNG data URIs are written to persistent storage.

## What this does not change

- No geometry, station dispatch, chain physics, bank interpolation or share/save schema modifications.
- No AI-generated assets. The blueprint is rendered from the user's actual spline using a 2D canvas, not produced by an image generator.
- No new game dependency or build process. `IntersectionObserver` is a browser API; the fallback remains functional without it.
- This release does not establish an actual measured 60 FPS target, nor claim visual parity at DPR 3.
- The classic preset physics reference remains **27.45s / 88 km/h**.

## Test commands

Run editor and library tests with just Node:

```sh
node tests/editor-runtime-regression.mjs
node tests/library-render-regression.mjs
```

For the full fixed-physics and support-clearance suites (test-time dependency only):

```sh
npm install --no-save --no-package-lock three@0.160.0
node tests/support-clearance-regression.mjs
node tests/physics-regression.mjs
```

The new library test extracts the actual `gamePixelRatio`, `libraryBlueprint`, observer helpers and cache from `play/index.html`. It tests a fake observer's visibility callback, no work for off-screen cards, a second appearance reusing the cached preview, detaching an old observer on library rerender, a 40-entry LRU, invalidation, immediate fallback without the API, and the DPR 3 -> DPR 2 cap. CI runs it on PRs and main pushes.

## Manual acceptance checklist

- [ ] Open a large library on desktop and iOS Safari: visible cards fill in, with no layout jumps; scroll to reveal more thumbnails.
- [ ] Reopen the same library and verify thumbnails reappear quickly; rename/duplicate/delete a coaster and confirm all remaining previews are correct.
- [ ] Change a coaster, save under the same name, and verify the blueprint reflects the new nodes rather than the old preview.
- [ ] Test a browser without IntersectionObserver using devtools or an older device: library still shows thumbnails.
- [ ] Verify a DPR 3 phone renders the 3D world at a capped ratio of 2. The editor and UI remain usable.
- [ ] On desktop with a 1x or 2x display, graphics stay unchanged; moving a window between monitors should refresh its raster scale.
- [ ] Check screenshot PNG export remains usable. GPU framebuffer ownership is unchanged.
- [ ] Run all presets and the shared 47.5m hill once after deployment.
