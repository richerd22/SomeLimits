# SomeLimits - November 18, 2026 playtest repair

## Principle

No modes, no roll-node taxonomy. The builder places points, drags things and rides.
No generated imagery; existing Three.js meshes and hand-drawn SVG only.
One playable HTML file lives at `play/index.html`. The site root now redirects
to it, retaining `#c=` share fragments (the old root was a full duplicate and
could go stale independently).

## What was wrong

1. Train started at 0 and crept at the 1.2 m/s anti-stall floor until a lift.
   The shared layout has a 37m flat approach before the hill; the first chain
   previously arrived **35.08 seconds** into the ride.
2. `getSpacedPoints(900)` is arc-length spaced but the code assigned lift
   and bank using `(sampleIndex / 900) * nodeCount`. Long and short stretches
   received the wrong segment's lift and banking, and inserting nodes from a
   ray hit could splice the wrong part of the array.
3. A no-drop circuit had no power source. 210m of flat track ran at the
   1.2 m/s anti-stall floor for **181.49 seconds**, despite being rideable.
4. A node drag projected to a horizontal 3D plane. Screen-up therefore moved
   x/z in the three-quarter camera view. The orange cap was the only obvious
   height gesture, and its first movement could jump by the cap's offset.

## Fix

- 6.5 m/s station-wheel dispatch, 7.0 m/s uphill chain.
- Sample node ownership from `curve.getUtoTmapping(u)` in both closed and
  open tracks. Roll remains on each existing node, with the same local
  cosine interpolation. No new objects or editor modes.
- Flat circuits (less than 2m between highest and lowest nodes) get a
  6.5 m/s tire-drive floor outside the braking zone. These are **powered**
  circuits, not gravity rides; the game says so. Lift overrides on flat
  tracks do not disable tire drive.
- Direct lime-node drags choose a screen axis after an 8px (mouse) /
  13px (touch) dead zone. Predominantly up/down edits height in a
  camera-facing vertical plane; predominantly sideways edits x/z.
  The choice holds for that gesture. Existing orange cap and precise
  height slider remain. All drag positions are relative to the press,
  avoiding first-frame jumps. Height moves never smooth themselves.
- Station taps still close open builds; an actual upward touch drag cannot
  accidentally trigger that closure. Correct segment indices are used
  for inserting nodes into uneven loops.

## Reference numbers: before -> after

Headless fixed-step (1/60s) simulation using the game's exact CORE and
Three.js r160 Catmull-Rom math. Rounded lap-screen values may differ by 0.1s
depending on browser frame pacing.

| Layout | Lap before | Lap after | Max speed before | Max speed after |
|---|---:|---:|---:|---:|
| Classic | 47.84 s | **27.45 s** | 86 km/h | **88 km/h** |
| Oval | 33.42 s | 22.22 s | 75 km/h | 77 km/h |
| Wild | 52.88 s | 31.44 s | 90 km/h | 92 km/h |
| Looper | 62.85 s | 38.08 s | 73 km/h | 75 km/h |
| User's 47.5m climb | 89.91 s | **61.62 s** | 90 km/h | 91 km/h |
| Flat 210m loop | 181.49 s | **38.40 s** | 4 km/h | **23 km/h** |

For the linked user circuit, first chain contact changes **35.08 -> 5.42 s**,
first crest **41.85 -> 14.42 s**. Track lengths and node heights are unchanged.

**The classic reference moved intentionally.** Its previous fingerprint
was 47.8s / 86 km/h. The new one is **27.5s / 88 km/h**. The correction
affects the same lift and station physics on every coaster, including the
classic; no hidden preset exemption. Update automated baseline checks.

## Verification and limitations

- Full module passed JavaScript syntax parsing.
- Four preset laps, the playtest layout, and a flat circuit completed in
  the headless fixed-step simulation. A standalone regression harness
  lives at `tests/physics-regression.mjs`.
- No changes to JSON/share schemas, banking fields, station selection, or
  imported point formats.
- WebGL and actual mouse/touch browser interactions were not exercised
  through an automated browser in this environment. Test those manually
  after deployment, especially the selected node's height gesture,
  diagonal drag classification, two-finger cancellation, cap precision,
  share redirects, and screenshots.

To run the repeatable physics regression locally:

```sh
npm install --no-save --no-package-lock three@0.160.0
node tests/physics-regression.mjs
```
